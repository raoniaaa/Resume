项目概览个人职责系统架构核心模块技术取舍项目结果

01 / OVERVIEW

把 GEO 从监控工具扩展为有证据、有内容、有计费的生产平台。

平台面向品牌方与营销机构，将 MCP 舆情采集、多模型可见度监控、品牌 RAG、结构化报告和内容发布组织为有状态长任务。核心挑战是保证各阶段使用同一版本上游数据，在重启、取消、重试和多租户并发下仍保持执行、证据与资金流水一致。

LINEAGE

长链路必须使用同版数据

分析、QRW、探针、监控和报告均绑定上游数据版本；发现旧结果或缺失阶段时阻断下游，避免新旧数据串用。

KNOWLEDGE

知识既要问答，也要写作

同一资料生成通用问答 Chunk 与品牌、产品、竞品关系、用户问题、GEO 规则和文章模板等结构化知识条目。

CONTENT

生成内容必须证据可追溯

文章事实绑定证据编号，经过确定性校验、语义审校、自动改稿和发布硬门禁，禁止补写未知功效、数字和竞品结论。

COMMERCE

执行状态必须与计费一致

B2B 租户钱包与 B2C 用户钱包支持动态定价、成功结算、失败退款和幂等扣费，断点续跑不会重复计费。

02 / RESPONSIBILITY

负责 Agent 主链路、知识库、内容生产和商业化工程。

01

工作流与数据血缘

以持久化状态机管理 MCP、清洗、QRW、探针、监控与报告，加入版本血缘、任务取消、失效控制和 Prompt 动态版本加载。

02

自适应采集与公平调度

规划 8–12 组 Query 并按有效评论目标自动补采；实现 fairLimiter、分层并发、429 冷却、Checkpoint 和同日结果缓存。

03

双投影品牌 RAG

完成多格式解析、重叠分块、1024 维向量、HNSW 索引、SHA-256 去重、知识冲突隔离与文档图片资源提取。

04

证据约束内容 Agent

构建检索、规划、初稿、校验、审校、改稿、配图和发布流水线，并保存每轮 Draft、Review 与 Revision。

05

并行结构化报告

并发生成 Overview、Landscape、Actions，对 JSON 和业务结构自动修复，量化指标由监控程序结果覆盖模型生成值。

06

白标 SaaS 与计费

实现三级账户、BFF、双层钱包、billing_ref 幂等结算、失败退款、支付验签、Webhook 和双维度限流。

03 / ARCHITECTURE

平台层负责边界，工作流层负责执行。

请求从三类用户入口进入 BFF 与业务 API，经 Tenant 上下文确定隔离范围，再进入 Agent 工作流。每个阶段将状态、结果和用量写入持久层，缓存只用于减少可重复计算，不替代真实业务状态。

04 / CORE MODULES

从舆情采集到公开发布的八个核心模块。

01

自适应 MCP 采集

品牌词、品类词和模型结果生成多组 Query；多轮采样、Feed 去重和评论目标共同控制规模，不足时自动扩大范围补采。

02

评论清洗与 QRW

提炼主题和真实用户问题，支持人工修订；品牌词、品类词、场景词和需求词分层生成并持久化为可追踪资产。

03

混合路由监控

pure/mixed 策略按租户、用户和模型配置 API 比例，将真实客户端采样与批量 API 结合，平衡真实性和成本。

04

公平并发与恢复

fairLimiter 按 Task Key 轮转执行槽，叠加全局、任务和模型并发；Checkpoint、冷却、重试和缓存降低失败成本。

05

双投影品牌 RAG

PDF、DOCX、PPTX、XLSX 等资料同时生成问答索引和 GEO 写作知识，冲突内容隔离出写作上下文。

06

内容审校与发布门禁

最多三轮审校改稿，检测无效证据、无引用数字、绝对化宣传、竞品贬损和内部口径泄漏。

07

结构化报告

三段报告并行生成，执行 JSON、字段与业务结构校验；提及率和模型覆盖度以程序计算结果为权威。

08

双层钱包

B2B 与 B2C 钱包支持产品定价、会员免扣、成功后结算、失败退款、用量审计和低余额拦截。

05 / ENGINEERING DECISIONS

关键取舍围绕隔离、恢复与成本展开。

工作流状态入库

仅依赖前端步骤状态更简单。

选择服务端 stage/status/progress 与前置校验，换取刷新恢复、失败重试和跨端一致性。

缓存清洗结果

每次重新清洗最直接，但重复消耗采集和模型资源。

以品牌和 Feed 作为缓存维度，并设置 24 小时有效期，在时效和成本之间取平衡。

BFF 隐藏密钥

浏览器直连平台 API 开发量更小。

由 BFF 注入官方 Key 并代理业务接口，避免密钥暴露，同时承接白标前端和浏览器会话。

租户公平限流

全局并发池可能被单个大租户占满。

按租户策略分配官方 API 与 MCP 请求，让共享资源在多个租户间保持可预测。

06 / OUTCOME

形成可审计、可恢复、可发布和可计费的 GEO 平台。

8–12 Queries

2 Projections

Success Billing

成功结算、失败退款、Checkpoint 恢复不重复计费。
