01 / OVERVIEW

让流程、规则与 AI 各自解决擅长的问题。

医保审核和处方流转需要确定性流程，医疗问答需要高质量检索，实时患者与库存数据又必须通过受控工具获取。平台将三类能力解耦，再通过多租户、合规拦截和统一工具规范组合成可落地的医疗业务系统。

PROCESS

审批与规则混在代码中

Flowable 负责长生命周期审批，LiteFlow 负责可组合业务规则，减少医保报销和处方逻辑硬编码。

KNOWLEDGE

通用分块不适合医疗文档

围绕证型、方剂和禁忌设计三级语义结构，并使用统筹区、生效日期等元数据限制检索范围。

REALTIME

模型知识无法替代业务数据

将医保结算、患者医嘱和药品库存等 8 个 REST API 封装为 JSON Schema 工具。

COMPLIANCE

会话包含敏感信息

请求层脱敏 PHI，响应层过滤不合规建议，会话层隔离租户和用户上下文。

02 / RESPONSIBILITY

负责 Agent、RAG、工具与安全链路的核心后端。

01

高可信医疗 RAG

设计医疗语义分块、混合检索、RRF 融合、Rerank 精排、元数据过滤与答案引用溯源。

02

业务工具标准化

将 8 个核心 REST API 封装为 Function Calling 工具，以 JSON Schema 约束入参出参。

03

Advisors 合规管道

实现 PHI 正则脱敏、敏感内容过滤和对话限流，防止患者标识和不合规诊疗内容进入模型链路。

04

多轮记忆与 MCP

使用 Redis 持久化会话窗口，并以 tenantId:userId:sessionId 作为上下文键；通过 MCP 统一工具注册边界。

03 / ARCHITECTURE

确定性流程包围概率性模型。

用户请求先经过租户、身份和 PHI 安全检查，再根据意图进入知识检索、实时工具或业务流程。Agent 只能在检索证据、工具结果和流程权限允许的范围内生成答案。

04 / CORE MODULES

从业务编排到可信回答的六个核心模块。

01

双流引擎

Flowable 管理审批状态和人员任务，LiteFlow 管理业务规则节点，使流程结构与规则判断可以分别配置和演进。

02

三级医疗分块

针对指南与目录结构按“证型—方剂—禁忌”组织语义块，保留医疗上下文而非机械按字符切分。

03

混合检索与精排

向量检索和 BM25 并行召回，RRF 融合排序，再以 bge-reranker-v2-m3 精排 Top-K 候选。

04

元数据与引用

按医保统筹区、生效日期等条件过滤知识，并强制答案标注原文出处章节，提高规则类回答可核验性。

05

实时业务工具

Agent 解析自然语言意图，调用医保结算、患者医嘱和药品库存服务，以结构化结果返回前端。

06

持久化记忆

PersistentChatMemoryStore 与 Redis 保存消息窗口，支持跨请求追问用药禁忌等连续场景，同时隔离租户与用户。

05 / ENGINEERING DECISIONS

医疗场景的取舍优先考虑可追溯与合规。

双流引擎

把所有逻辑写入 Flowable 节点统一但臃肿。

审批生命周期交给 Flowable，细粒度规则交给 LiteFlow，保持职责清晰。

混合检索 + Rerank

单向量检索链路更短。

医疗目录含大量精确术语，BM25 补充关键词召回，RRF 与精排提高相关性。

元数据先过滤

让模型在所有文档中自行判断适用地区与日期风险较高。

检索阶段就限定统筹区和生效日期，减少过期或异地规则进入上下文。

分层安全拦截

单次 Prompt 声明合规要求实现容易但不可控。

在请求、响应和会话三层执行脱敏、过滤与隔离，使安全能力独立于模型表现。

06 / OUTCOME

把医疗 Agent 放进可治理的业务边界。

8 Tools

医保结算、医嘱、库存等核心接口进入标准工具链。

Hybrid RAG

向量、BM25、RRF、Rerank 和元数据过滤形成检索闭环。

Traceable

回答保留原文出处，并经过 PHI 与合规内容过滤。
