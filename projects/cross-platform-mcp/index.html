02 / SELECTED CASECROSS-PLATFORM MCP AUTOMATION

Cross-Platform MCP跨端智能自动化与多模型接入平台

将浏览器网页端和 Android 真机端的 AI 问答、社交媒体采集、信源提取、账号管理与批量监控统一封装为标准 MCP Tools，为上层 Agent 与业务工作流提供一致、可调度的执行层。

01 / OVERVIEW

让上层 Agent 不再关心工具运行在哪个终端。

不同 AI 平台存在网页端与移动 App 能力差异，账号登录态、动态页面、设备资源和失败模式也各不相同。项目以统一 MCP 契约屏蔽执行环境，将浏览器 Session、Android 真机、账号池与批量任务组织成可路由、可恢复、可观测的工具平台。

PROTOCOL

工具定义容易分散

Tool Schema、参数校验、Handler 和返回结构集中管理，同时提供 Stdio、Streamable HTTP 与业务 Gateway，避免上层系统适配多个私有协议。

RUNTIME

网页与 App 能力不同

浏览器侧适配 Chromium、Camoufox 和动态 DOM，移动侧通过 ADB、UIAutomator 与配置化 UI Profile 控制真实 Android 应用。

RESOURCE

账号和设备不能并发争用

Least-Active 选择、独占租约、等待队列、失败换号换机与冷却状态共同约束共享资源。

CLUSTER

本地 Profile 绑定具体节点

Redis NX 租约、Home Node 与跨节点转发让统一 Gateway 能把请求送到真正持有浏览器 Profile 或设备的节点。

02 / RESPONSIBILITY

覆盖 MCP 协议、双端执行、资源调度和集群治理。

01

MCP Server 与工具契约

基于官方 SDK 实现 Tool 定义、Schema 校验、Handler 动态注册、标准错误封装与结构化结果，并统一 TypeScript 与 C# 两套工具契约。

02

浏览器自动化适配器

抽象 BrowserProvider，适配 Chromium 与 Camoufox；封装登录、搜索、详情、评论、问答与信源提取，并处理回答稳定性与动态 DOM。

03

Android 真机 MCP 网关

使用 ASP.NET Core、ADB 和 UIAutomator 完成设备注册、无线配对、App 启动、会话初始化、输入发送、完成检测与来源提取。

04

资源池与故障恢复

实现多账号、多设备租约、排队、冷却、失败切换、批量任务恢复和资源 Lease 回收，确保异常退出后执行资源可重新使用。

03 / ARCHITECTURE

统一入口路由到不同节点、账号和执行终端。

调用方通过一致的 MCP Tool 契约提交请求。Gateway 完成账号或设备选择、Home Node 发现和跨节点转发；目标节点获取 Redis 租约后，选择浏览器 Adapter 或移动 MCP 网关执行，并将结果、信源和审计信息标准化返回。

04 / CORE MODULES

六个模块构成跨端 MCP 执行底座。

01

多协议 MCP Server

工具元数据与执行 Handler 解耦；Zod 和 .NET Attribute 约束参数、只读属性、可选字段与默认值，兼容本地和远程调用。

02

双浏览器引擎

统一 BrowserProvider 屏蔽启动、连接、页面操作和状态持久化差异，并为目标网站建立独立 Adapter。

03

移动端 UI Profile

用文本标记、Resource ID、坐标和页面层级组合定位控件，支持回答页面、信源面板和分享结果的多路径来源抽取。

04

账号与设备调度

Random 与 Least-Active 选择可用实例；同一 Session 或设备使用队列与信号量串行执行，失败后切换未尝试资源。

05

分布式集群协调

Redis NX Lock 配合随机 Token、TTL 和自动续期实现跨节点互斥；Home Node 保证 Profile 请求被路由到正确节点。

06

批量任务与运维

异步任务返回 Job ID，支持进度、结果和取消；启动时恢复 Queued/Running 任务，并输出审计日志、SignalR 实时状态和 Prometheus 指标。

05 / ENGINEERING DECISIONS

关键设计围绕协议一致性和资源安全展开。

统一工具契约

为网页端和真机端分别暴露接口实现更直接。

统一核心参数和返回结构，让上层 Agent 可以按能力动态选择终端而无需改造调用逻辑。

独占资源租约

允许同一账号并行操作吞吐更高，但会互相修改页面和 App 状态。

同一 Session 或设备串行化执行，并通过等待队列提升可控性。

持久化与运行态分离

所有状态都放 Redis 便于共享，但不适合长期账号元数据。

文件、PostgreSQL 或 MySQL 保存元数据，Redis 只承担租约、心跳与路由协调。

Home Node 绑定

任意节点接管请求更均衡，但本地浏览器 Profile 无法透明迁移。

保存资源所属节点并由 Gateway 跨节点转发，保证登录态与实际运行位置一致。

06 / OUTCOME

从单机脚本升级为通用、可扩展的 MCP 执行平台。

2 Terminals

浏览器网页端与 Android 真机端共享核心工具契约。

3 Protocols

支持 Stdio、Streamable HTTP 与统一业务 Gateway。

Cluster Ready

租约、心跳、Home Node、跨节点路由和任务恢复支撑多节点扩展。
